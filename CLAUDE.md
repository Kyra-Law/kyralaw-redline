# CLAUDE.md

Guidance for Claude Code working in this repository. This repository is intended to be public.

## Rules

1. **No client or confidential material, ever.** No document text, party names, matter
   references or figures from real agreements, in code, comments, docstrings, tests, fixtures,
   corpus files or commit messages. When a real document exposes a bug, reproduce it with invented
   text of the same shape, and check that the new test fails with the fix removed. The evaluation
   corpus is synthetic by design; never add real documents to it.
2. **Do not push without an explicit instruction.** Committing locally is fine.
3. **No em dashes** in any output: code, comments, docs, commit messages.
4. **The renderers compute no diff of their own.** `docx_io.py` (rebuild) renders exactly the
   segments `compute_redline_segments` produces, and `inplace.py` (in-place) exactly what
   `align_paragraphs` produces; both live in `diff.py`. A second diff in either renderer makes the
   shipped file a different algorithm from the one the tests and the evaluation measure, and the
   two renderers would stop marking the same changes. The one liberty `inplace.py` takes is with
   tables (`_respect_tables`): a pair that crosses table rows is shown as a deletion plus an
   insertion, and paragraphs then left without a partner in corresponding cells are aligned again
   by `align_paragraphs` itself. Every word diff still comes from `diff.py`.
5. **Never fail silently.** A skipped pair, an integrity failure or a missing input is reported
   with its magnitude, never folded into a score.

## The evaluation

- Every algorithm the evaluations run is a `RedlineEngine` (`src/kyralaw_redline/engine.py`): a
  lowercase-hyphenated `name` and `redline(old_docx, new_docx) -> bytes`. A new one is a subclass,
  listed in `ENGINES` in `eval/run_eval.py`.
- The corpus (`eval/corpus/v4.jsonl`; `v1` to `v3` are frozen earlier versions) is generated by `eval/generate.py` and committed. CI fails if
  the two disagree. Changing the generator means regenerating and committing the corpus in the
  same change; changing what the benchmark measures means a new corpus version (`v5` next), not
  rewriting the current one, so published scores stay comparable.
- The ground truth must stay exact by construction. The generator checks that the recorded
  deletions and insertions account for every token; it also has to stay minimal, so a
  substitution may not share a token with what it replaces.
- `eval/render.py` decides only how a version looks. It must never change the text a reader
  extracts; `run_eval.py` stops if a rendered version does not read back as the corpus text.
- `run_eval.py --min-score` in CI is a regression floor. Raise it when the score improves; never
  lower it to make a change pass.
